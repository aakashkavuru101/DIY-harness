# S4 Slice

Purpose: a build order that works end to end at every step.

At L0 this stage is skipped: the S3 gate wrote the build's one ticket into `STATE.md`. If `STATE.md` names S4 at L0, set the stage to `S5 Build` and carry on there.

1. Call the Skill tool with `grilling`. Read [the to-tickets playbook](../playbooks/to-tickets.md) and follow it on `.harness/SPEC.md`: one tracer-bullet ticket per part, or per batch of a wide change. A part that is already there gets no ticket. Each ticket's acceptance is its part's proof, and each names the tickets that block it. In a repo with no check command, QA1 is ticket 01: the other proofs run through it.
2. Show the list before any file is written: number, title, part ID and blocked by, at most 5 tickets per reply. Ask whether the granularity and the blocking edges are right, in the grilling format, so "yes" accepts the list.

The gate. Once the user approves the list:

- write the ticket files, as the playbook's last step says;
- in `STATE.md`, set the stage to `S5 Build`, the current ticket to the first unblocked ticket, and the next step, and log the approval;
- stop, and ask whether to start S5.

Done when: the user has approved the ticket list, and `STATE.md` names the first unblocked ticket.
