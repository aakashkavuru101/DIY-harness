# S3 Design

Purpose: the smallest set of parts that meets the goal.

Until this stage's gate, apply ponytail at its ultra level: question every part, the ones the user asks for included.

Before the first round, read [PARTS.md](../PARTS.md), [LEVELS.md](../LEVELS.md), where "Minimal by default" says when a part's trigger has fired, [GUARDRAILS.md](../GUARDRAILS.md), and the newest `.harness/research/audit-*.md` if there is one. Then call the Skill tool with `grilling`.

## At every level

- **Reuse first.** What the repo already has (a test or lint script, a hook manager, a deny rule, a steering file) is the part: it gets a line in the spec and no ticket. Propose new tooling only when nothing there does the job.
- **Park what is not earned.** For a part the user asks for whose trigger has not fired, recommend parking it and name the failure that would earn it. If the user insists on a part at or below L1, design it and record the override.
- **Parts up to L1.** This command builds parts up to L1 for now. Park each higher part with that reason; if the user overrides, record it and tell them it is not built yet. The failure log (KN8) is written at S6: park it until then.
- **Threats.** Walk T1 to T10 in GUARDRAILS.md and keep only those that are real for this repo. Each kept threat gets a part from its "Stopped by" cell, at or below the level.
- **No safety fact is dropped.** A safety fact that a parked part, or a level below the one you proposed, leaves unanswered goes under the open decisions in `STATE.md`, whatever the level. Until a sandbox exists, recommend tier B.

## At L0: one reply

Put the whole design in one reply, in the grilling format, so "yes" approves it as the spec:

- the always-built parts, PR2 and QA1, each with where it lives and its proof. PR1, CO1 and CO2 are already there;
- the threats that are real for this repo, one line each: what stops it at L0, or that nothing does;
- the build's one ticket: its title, and as its acceptance the proofs of the parts.

Once the user approves, write two sections into `STATE.md`:

- `## Spec`: one line per part (its ID, what it answers, where it lives, its proof), then a `Parked:` line and an `Overrides:` line;
- `## Ticket`: the ticket's title and its acceptance.

Set the current ticket to it and the stage to `S5 Build`: S4 is skipped. Log the approval, then stop, and ask whether to start S5.

## At L1 or above

1. Walk the five planes in order: Protocol, Cognition, Knowledge, Integration, Quality. One round per plane. Offer only parts at or below the level in `STATE.md` whose trigger has fired, each with the goal line or the observed failure it answers. A plane with no such part gets one line saying so, and no round. After each round, write what is agreed so far (the parts, the parked ideas, the overrides) into `.harness/SPEC.md`, from the template and headed `# SPEC (draft, not approved)`, so a fresh session can carry on from it.
2. Run one more round on the threats you kept.
3. For each part, state what it answers, where it lives in this repo, the adapter each agent under "Runs in" needs, if any, and its proof: the part's "Proved by" cell made concrete, as a command or a test that goes red without the part. For QA3, name the seams; call the Skill tool with `codebase-design` when where a seam belongs is in question.
4. When a design question needs a runnable answer, call the Skill tool with `prototype`. For an external fact, such as an agent's hook or settings format, call the Skill tool with `research`. For a new term or a hard-to-reverse decision, call the Skill tool with `domain-modeling`.
5. Read [the to-spec playbook](../playbooks/to-spec.md) and follow it: it completes `.harness/SPEC.md` from the template. The heading keeps its draft mark until the gate. Skip its question about seams unless QA3 is a part.

The gate. Show the spec and ask the user to approve or change it. Once they approve, change its heading to `# SPEC` (after "just do it": `# SPEC (approval skipped <date>)`), set the stage to `S4 Slice` and the next step, log the approval, then stop, and ask whether to start S4.

Done when: every part names what it answers and its proof, every other idea is under Parked with the failure that would earn it, and the user has approved the spec.
